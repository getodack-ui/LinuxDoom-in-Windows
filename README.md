# LinuxDoom-in-Windows

Порт исходников **DOOM (linuxdoom-1.10)** для Windows и Visual Studio.

## Что изменено

Взяты исходники официального релиза id Software (GPL, см. [`LICENSE.TXT`](LICENSE.TXT)). Из оригинала убраны X11, OSS-звук и сокеты, добавлен слой Win32 с выводом графики через GDI.

## Быстрый запуск

В папке `run` лежит готовая 32-битная сборка MinGW: `doom_mingw.exe`. Visual Studio для запуска не нужна. Запустите её из папки `run`; рядом должен быть файл WAD с данными игры (`doom1.wad`, `doom.wad`, `doom2.wad`, `plutonia.wad` или `tnt.wad`).

```powershell
cd .\run
.\doom_mingw.exe
```

Можно указать параметры командной строки, например:

```powershell
.\doom_mingw.exe -warp 1 1
```

## Сборка в Visual Studio

1. Откройте `DoomWin.sln` в Visual Studio 2019 или 2022 с нагрузкой **«Разработка классических приложений на C++»**.
2. Сначала распакуйте `src.zip` в корень репозитория: проект ожидает папку `src\` рядом с `DoomWin.sln`.
3. Выберите платформу `x86` (`Win32`). `x64` не поддерживается: в коде Doom 1993 года указатели хранятся в `int`, и на 64-битной сборке игра падает.
4. Поместите файл WAD в `run\`. Сборка Release создаёт `run\doom.exe`, а Debug — `run\doom_debug.exe`. В Visual Studio рабочей папкой для запуска задана `run\`.

Сборка MSVC автором не проверялась. Если возникнут ошибки, сохраните и пришлите полный текст ошибок сборки.

## Управление

- Стрелки — ходить и поворачивать.
- `Ctrl` — огонь; `Пробел` — открыть или использовать; `Shift` — бег.
- `Alt` + стрелки — боковой шаг.
- `1`–`7` — выбрать оружие; `Tab` — карта; `Esc` — меню.
- `F1`–`F12` — функции меню.
- Мышь захватывается во время игры, в меню остаётся свободной: левая кнопка — огонь, правая — боковой шаг, средняя — вперёд.
- `Alt` + `Enter` — полный экран; `Alt` + `F4` или кнопка закрытия окна — выход.

## Параметры командной строки

| Параметр | Действие |
| --- | --- |
| `-2`, `-3`, `-4` | Масштаб окна (по умолчанию `-3`) |
| `-fullscreen` | Запустить в полноэкранном режиме |
| `-nomouse` | Отключить мышь |
| `-warp E M` | Сразу перейти на эпизод `E`, уровень `M` (например, `-warp 1 1`) |
| `-skill N` | Установить сложность |
| `-file pwad` | Подключить дополнительный WAD |
| `-devparm` | Включить режим разработчика |

Поддерживаются и другие параметры оригинальной игры. Настройки сохраняются в `default.cfg` рядом с запускаемым файлом.

## Ограничения

- Звука и музыки нет: в `src\win32\i_sound.c` находятся заглушки.
- Сетевой игры нет: `src\win32\i_net.c` предназначен только для одиночной игры.
- Демо старых версий (109) оригинальный код не проигрывает.

## Изменения в исходниках

Остальные оригинальные файлы не изменены. В частности:

- `w_wad.c` — убраны самодельные `strupr` и `filelength`, добавлено `O_BINARY=0`; на Windows WAD должен читаться в двоичном режиме.
- `m_menu.c` — добавлен `O_BINARY` при чтении описаний сохранений.
- `d_main.c` — конфиг `default.cfg` вместо `~/.doomrc`, `_mkdir` вместо `mkdir`.
- `d_net.c` — `I_Yield()` в цикле ожидания тика, чтобы не загружать процессор на 100%.

POSIX-заголовки-заглушки находятся в `src\compat\` (`unistd.h`, `values.h`, `alloca.h`, `win_compat.h`). `win_compat.h` подключается ко всем файлам при сборке.

## Проверка

По описанию проекта, сборка кросс-компилятором MinGW (`i686`) была запущена под Wine с Freedoom; проверены меню, рендеринг, клавиатура и `Alt` + `Enter`. Сборка MSVC не проверялась.
